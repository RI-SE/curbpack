# Epics and user stories

This is the **user-facing backlog**: what people need to accomplish and how they recognize success. It is not the implementation specification.

- `epics/01-pack-editor/` contains **EP-01 — Complete Functional Pilot**. The directory name is retained to avoid an unrelated rename. [SYS-03](epics/01-pack-editor/stories/SYS-03-one-repo-door.md) is the pilot door: one repository, its `curbpack.json`, and a packs root. PE-01–PE-11 cover Pack Editor; CHK-01–CHK-04, REV-01–REV-02 and SYS-01 extend the epic through working Checks and a signed Review. [DOC-04](epics/01-pack-editor/stories/DOC-04-single-persistent-model.md) is a draft model-alignment story; `docs/reference/packs2.md` remains normative, Pydantic implements it, and JSON Schema is generated.
- `epics/02-modularize-studio/` contains **EP-02 — Architecture migration**, targeting the two-system design in `CURBPACK_ARCHITECTURE.md`, after the baseline and VR-00/VL-00 contract work.
- `epics/09-standalone-tools/` contains **EP-09 — Headless CLI interfaces**. Draft, subordinate to EP-02. No separate UI processes or `pilot_app` product; CLI uses the same backend operations as REST.
- `epics/12-development-environment/` contains **EP-12 — Development environment**. Draft. One container, built and started with Make. CI calls that same build. Not authorization to implement.
- `epics/04-studio-doc-truth/` contains **EP-04 — Studio documentation truth**. DOC-01–DOC-03 are done: the SDD account under `daniel/ny_sdd/`. [DOC-06](epics/04-studio-doc-truth/stories/DOC-06-published-reader-docs.md) updates the published documents a reader opens from the repository README. It is draft, it does not edit `daniel/ny_sdd/` or `docs/reference/packs2.md`, and it is not authorization to edit a document until that document is the current row.
- `epics/13-developer-guides/` contains **EP-13 — Developer guides**. Draft. How-tos for an extension the code already supports. [DOC-05](epics/13-developer-guides/stories/DOC-05-document-regulation-adapter.md) is the regulation-adapter guide. It does not block EP-01 and is not authorization to implement.
- `epics/14-regulation-adapters/` contains **EP-14 — Regulation adapters**. Draft. CRA text annexes II, V, and VIII from the CTAM poc. NIS2 is not in that poc. It does not block EP-01 and is not authorization to implement.
- `epics/16-text-dump-split/` contains **EP-16 — Text dump split**. Draft. Stage 00 splitting one full text into the adapter's sections. The behavior used to be described in `requirements/ARCHITECTURE.md` and is not implemented. Not authorization to implement.
- `epics/15-file-format-versions/` contains **EP-15 — File format versions**. Draft. `curbpack.json`, Pack, Requirement, and Claim each carry a format version. A reader walks one function per step, in memory. Save is separate. [FMT-01](epics/15-file-format-versions/stories/FMT-01-version-and-upgrade-chain.md) is not authorization to implement.
- `epics/11-pack-version-lifecycle/` contains revised **EP-11 — Pack identity, exchange and traceability**, VR-00 and VL-00–VL-06. The new ZIP exchange extends completed PE-11 and takes precedence for the future workflow. New functionality follows the placement rule in that epic.
- `DECISIONS.md` records product decisions and open questions. Only accepted stories and derived requirements authorize implementation.
- CHK, REV and SYS still need formal requirements and acceptance tests derived and checked against the actual pilot. Do not assume the UI proves their behavior.

Flow: **Epic → Story → formal requirement (`docs/req/`) → test evidence (`docs/test/`, `tests/`) → implementation**. One story may produce several requirements; keep IDs stable and link them.
