## Decisions recorded for this plan

- The resolver is a headless function in `studio/review/resolve.py`. The product repository named by the open `curbpack.json` is the only tree it reads. Git commands use `git -C` on that repository and do not fetch.
- A current Requirement matches only when its `namespace`, `pack_id`, and `id` equal the recorded identity and `version_digest` equals `requirement_digest`. A current Claim matches only when its id equals the Run Result row `id` and `version_digest` equals the row `digest`.
- Otherwise the resolver walks local commits that touch a file named `<requirement id>.json` or `<claim id>.json`. It parses each blob and accepts the newest commit whose object has the same identity and the same `version_digest`. The returned object is hashed again before it is reported. A current object with a different digest is reported as the current difference, not as the match.
- A Run Result row without the VL-04 binding fields leaves the Requirement link unresolved and still resolves the Claim from `id` and `digest`. The file is not rewritten.
- Check correspondence compares the resolved Claim's `checks` with the row's `checks` by `index`, `check`, and `args`. Recorded outcomes stay as stored. Checks are not run.
- One unresolved link does not stop the remaining links.
- An object `signed` block is read with `read_signature`. Its method is `object`. When that block is absent, the VR-00 Git reading runs against the recovered commit, not against the latest commit of the current path. `git_commit_signature` and `git_content_result` stay unused for a historical object because both describe the current file. Trust stays `%G?` equal to `G`, and the signer stays `%GS`. The method is `git` when that reading exists and `none` when it does not. A matching digest does not set the signature to valid.
- Comparison reuses `requirements.compare._changed_fields` and then keeps the `EDITABLE` names `extraction_review` already shows. That list omits `origin`, `status`, and `signed`. It does not write a working copy and does not call `compare_copies` or Apply.
- `review/present.py` and `app/review_model.py` receive the resolver result and copy it into the presentation. The existing sentence that a previous Requirement relationship cannot be established stays only for an unresolved digest. The Review page prints that presentation. It does not decide a match, a commit, or a signature.
