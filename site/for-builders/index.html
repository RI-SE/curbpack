For builders

Install, init, and check—green gates in your repo in under ten minutes.

Not conformity assessment. Not CE marking. Not a notified-body opinion.

Pick exactly one first move:

Two ways in — same local check

  1. Write then check — init (or optional warm-start), draft house docs on pack paths, then check.
  2. Bring docs then check — place existing policies on pack paths, then check. No portal PDF ingest — files in the repo only.

CI can run check alone. Review pack → human attest either way.

1. Safe try

curl -fsSL https://raw.githubusercontent.com/afelin/cyberready/main/scripts/install.sh | sh
cyberready doctor
cyberready demo

demo prints a one-pager path. Add --open only if you want the OS to open it. Pin @v0.4.3.

2. Product repo

cd /path/to/your/product
cyberready init
cyberready check

Default pack is house-policy. Opt into regulation-shaped checklists with cyberready init --packs cra-baseline or medtech-iec62304 (structural drafts — not legal conformity). Before a review wave: prepare-release (or share), hand the buyer one-pager, then a human attest.

3. CI

- uses: afelin/cyberready@v0.4.3
  with:
    heal: "true"

Drop-in example: repo examples/workflows/cyberready-check.yml.

Recipes: 60-second paths. Sample without demo: buyer one-pager.

Works with assistants — run the CLI, then cyberready export --context-pack. Optional thin MCP: repo examples/mcp. Contract: docs/assistant-loop.md.
