# Substantial-modification screening — delivered (not deferred)

> Maintainer note. Scrub target for work-order folklore.

**v3.1 / v4 work orders listed “substantial-modification screening” as deferred.** That capability is **delivered** by:

```bash
curbpack review --repo [path] --since <prior-report.json>
```

Two offline records of the same repository produce NEW / CLEARED / PERSISTING buckets. Exit codes are unchanged by `--since`. This is document triage — **not** a regulatory threshold; that judgment belongs to a human.

**Do not** re-add “substantial-modification screening” to deferred / non-goal lists.

See also: [`docs/stable-contracts.md`](../stable-contracts.md) review report contract; method docs under `docs/method/`.
