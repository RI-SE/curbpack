# VL-01 — Take ownership on cross-namespace edit

## Summary

- **Story:** `docs/agile/epics/11-pack-version-lifecycle/stories/VL-01-fork-pack-req-at-edit.md`
- **Goal:** Editing a Requirement in a Pack from another namespace asks for confirmation, then writes an unsigned copy of the whole Pack in the publisher's namespace. The original Pack stays as it was.
- **Scope / exclusions:** No merge, no upstream sync, no Claim rebinding, no directory-layout change, no Publish change. There is no TypeScript page host in this checkout, so the confirmation is rendered by the existing Requirement editor page. The copy itself is headless. Uncommitted files already in `docs/agile/` stay out of these commits.

## Decisions recorded for this plan

These follow the story and the VL-00 contract.

- `target_namespace` is `pack_namespace(namespace_base, pack["name"])`. For a Pack opened from a repository `packs_dir`, `namespace_base` comes from that repository's `curbpack.json` (`repo` on the form). For the selected working copy under the studio root, it comes from the open repository's `curbpack.json`. A missing file is an error. Do not substitute `RISE`. The comparison happens before any save, including a same-namespace save.
- A Pack whose `namespace` equals `target_namespace` uses the existing save. Namespace and origin stay as they were.
- A different namespace does not write on the first POST. The existing editor page shows the story's confirmation text, with Cancel and Take ownership. Cancel is a link back. Take ownership posts the same edit with an explicit confirmation field.
- The new Pack is a new dated working copy. The source directory is not opened for writing. A repo Pack stays at `packs_dir/<id>/<version>/`. The copy uses the existing `root/<id>/<timestamp>/` layout. No new path shape.
- The copy is built in a temporary directory and renamed into a free timestamp only after the Pack and every Requirement validate. Any failure deletes that temporary directory. The source bytes are not touched.
- Collision means another directory for the same Pack id, other than the source directory, already has `namespace == target_namespace`. Look under the studio root (dated working copies and `published/`) and under that repository's `packs_dir`. Reject before creating a directory. Do not overwrite or merge.
- The new Pack origin is the immediate source: `namespace`, `pack` (source id), and `version` (source `pack.version`). It has no `requirement` key. A source Pack origin is not copied forward.
- Each new Requirement origin is the immediate source: `namespace` and `requirement` from that source Requirement, `pack` from the source Pack id, and `version` from the source Pack version. A source Requirement origin is not copied forward.
- After those fields are set, the requested edit is applied to the one Requirement. `signed` is removed from the Pack and from every Requirement. `status` on the copy is `draft`. The source keeps its status and its `signed` block.
- The copy keeps the source `pack.version`. The new directory name is the timestamp. `origin.version` is that same source `pack.version`.
- Activation selects the new timestamp with the existing selection write. The redirect has no `repo` and no `pack` query, so the next open does not load the source Pack again.
- Claims are not moved or rewritten.
- The page shows three facts separately on `editor_page`: identity (`namespace` plus the ids), origin when the key is present, and the signature reading. The reading uses the words `valid`, `invalid`, and `unsigned`, taken from the existing signature result (`verifiable` and its reason). Object `status` is not that reading.
