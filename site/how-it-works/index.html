How it works

CyberReady checks your repository against local rule packs and writes a review pack you can hand to a buyer or auditor—on your machine, without claiming certification.

Not conformity assessment. Not CE marking. Not a notified-body opinion.

1. Rule pack

A rule pack is a JSON file of checks (files present, banned dependency versions, forbidden text patterns). Packs encode policy: house rules, Cyber Resilience Act (CRA)–style annex drafts, or sector templates. The binary does not hard-code an industry.

2. Local check

First move on a product repo: cyberready init then cyberready check. Check evaluates packs against your git repository on disk. Results are dual: machine-readable findings (JSON) and a short markdown report. Exit code 0 means gates passed on this tree; 1 means findings remain.

3. Review pack

prepare-release writes a review pack: layered reports, optional software bill of materials (SBOM) summary, and a buyer one-pager HTML. Daily check does not open or regenerate that HTML page.

4. Human review

A person reads the evidence and may run attest to bind a reproducible state hash into Git Notes. Unsigned attestations are labeled unsigned — not “verified.”

Check → evidence → human

CyberReady decides pass/fail (deterministic). Review pack and buyer one-pager are evidence for humans. Optional tutor packets propose only and must re-check; they never greenlight.
