## Decisions recorded for this plan

- Maintainer, 2026-11-12: the page is `studio/pack/pages/compare_form.ts`. A TypeScript compile step emits JavaScript. The existing Python server serves that file and JSON from the existing backend. No FastAPI and no frontend framework.
- The compile step is the `typescript` package only, used on a machine that already has Node. `tsc` writes `studio/pack/pages/compare_form.js`, and that file is committed. `node_modules/` is not committed. `make test` does not run `npm install` or `tsc`. The server serves the committed file and does not compile on a request. `tests/test_vl03_compare_form.py` runs `node --test` on that committed file, which needs Node already installed and does not download anything.
- The page is a browser script with no framework. It fetches the JSON and draws the form. The committed JavaScript exports the render and selection functions. Every changed leaf starts selected Old, so Apply with no further selection writes nothing.
- Changed leaves follow the Requirement editor, in this order: references; note; remediation_hint; strength; responsible; applicability; exceptions; scope; source framework, instrument, identifier, edition, language, url; discovery hint concepts, expected_evidence, path_hints, sources. A leaf is a choice only when its value differs. Unchanged leaves are text.
- A changed leaf is a disclosure, not a `select`. Its button opens two choices. Each choice contains the complete value in a `pre`. Old uses class `choice-old`: color `#991b1b` and `text-decoration: line-through`. New uses class `choice-new`: color `#15803d`. A multiline note remains readable in full when the disclosure is open.
- Select all old and Select all new set every changed leaf. A later change to one leaf leaves the others.
- Apply builds one `apply_extraction_choices` choice. A changed top-level leaf selected New is included in `fields` and the whole proposed value is copied. A changed top-level leaf selected Old is omitted. A changed leaf inside `source` or `discovery_hints` is not its own editable name. The `partial` parent starts as the current object. Each leaf selected New is replaced with the proposed value, including absence. Each leaf selected Old and each unchanged sibling stays at the current value. The merged parent therefore contains every key that exists on both sides, which is the shape `_is_blend` already accepts. A parent with no New leaf is omitted.
- Extract and Import use one comparison: `extraction_review(destination, proposal)`. Import does not get its own diff. The list query is `proposal` and `destination`, the same pair extract review already uses, plus `pack` and `repo` when the destination is a product pack. The script URL is `/requirements/compare/form.js`. The JSON URL is `/requirements/compare/form.json` with `requirement`, `proposal`, `destination`, and the same pack/repo keys. The form document is `/requirements/compare/form` with those keys. No update queue is stored. An operation that has no proposal shows no Changes links.
- Before Import calls `mark_selected`, it reads `read_selection`. When that selection is a working copy of the same pack id, the imported timestamp is `proposal` and the previous timestamp is `destination`. The redirect is `/requirements/copy?imported=1&proposal=<imported>&destination=<previous>`. The list then calls `extraction_review`. When no working copy of that pack id was selected, the redirect stays `/requirements/copy?imported=1` and there is no Changes link, because the operation has no pair.
- A requirement only in the proposal is an addition row on the list. Its New cell has a Changes link. Old means do not add it. New means add the whole proposed Requirement through the existing empty-fields path in `apply_extraction_choices`. Removing the JSON diff does not drop that add.
- Apply sends the selected New leaves through `apply_extraction_choices`, which already calls `apply_transfer`. Leaves left on Old are omitted. A destination outside the target namespace is not written in place; it uses the VL-01 confirmation already required by Compare apply.
- Cancel is a link to the same Requirements list, including the proposal query. It does not submit.
- After a same-namespace Apply, the browser opens the existing Requirement editor for that id.
- `/requirements/compare`, `/requirements/compare/apply`, and the extract-review JSON diff stay until the new page's tests pass. The last task then points the finished Extract at the list and removes the JSON-diff rendering. `tests/test_requirements_compare.py` currently expects that rendering; it is updated in that task, not weakened before the new page is proven.
