# VL-02 — Import and export Pack ZIP

## Summary

- **Story:** `docs/agile/epics/11-pack-version-lifecycle/stories/VL-02-import-export.md`
- **Goal:** A user exports a Pack as a ZIP of its existing directory and imports that ZIP into the Requirements workspace. File bytes, namespace, origin, version, and signatures stay as they were. Missing or invalid signatures are reported and do not block export or import.
- **Scope / exclusions:** The completed directory export (`export_pack` and the destination form on `/requirements/export`) stays. This story adds ZIP exchange. No ownership change on import. No merge, no Publish change, no new Packs v2 field, no directory-layout change. There is no TypeScript page host, so the ZIP controls are added to the existing Requirements pages. The exchange itself is headless. Uncommitted files already in `docs/agile/` stay out of these commits.

## Decisions recorded for this plan

These follow the story, the VL-00 identity, and the existing Extract workspace.

- ZIP export reads the selected working copy and stores each regular file's bytes under its path relative to that directory. `pack.json` is an archive member at the archive root. Dotfiles are included. `export_pack` is not called and is not changed.
- A symlink in the source directory fails the export before a ZIP is returned. The directory export form is unchanged.
- Import accepts an archive whose `pack.json` is at the archive root, and an archive whose only top directory contains that `pack.json` and every other member. Both are one Pack directory. The stored relative paths are the paths under that directory. Two Pack directories, a member outside that directory, an absolute path, a `..` segment, a backslash, or a symlink member is an unsafe or invalid archive.
- The archive is extracted into a sibling temporary directory under the studio root and renamed with `os.rename` into `root/<pack-id>/<timestamp>/` only after `load_pack_directory` accepts it. Any failure deletes the temporary directory and a partial timestamp directory. The Pack id must be a single path segment, and the final path must stay inside the studio root.
- Installed files are the extracted bytes. Import does not call `save_pack` or `save_requirement`, and it does not add `origin`, change `namespace`, change `version`, or remove `signed`.
- Collision is another Pack already under the studio root, including dated working copies and `published/`, with the same `namespace`, `id`, and `version`. Reject before creating the timestamp directory. Do not overwrite or merge. A Pack that exists only in a product repository is not this collision.
- After a successful import, `mark_selected` selects the new timestamp. The browser opens `/requirements/copy?imported=1`. That page prints the existing VR-00 rows (`status`, `method`, `reason`) for the Pack and each Requirement. Other copy-page visits do not gain that block.
- Export ZIP is a second control on the existing export page. It downloads the archive. The destination form still writes a directory. The signature rows already on that page are the export report. An invalid or missing signature does not turn the download into an error.
- Import is a file field named `archive` on Pack Sources (`/requirements`). The server reads a multipart body only for that post, and it reads the ZIP export body before the urlencoded form parser. Other forms stay urlencoded. The export ZIP post is the existing export form plus `exchange=zip`, which is distinct from the destination form. Choosing the file does not take ownership. A later edit of a foreign namespace uses VL-01.
- The editor's selected Requirement is the working copy from `resolve_selected_pack` when that selection is a working copy whose pack id is not the active adapter's pack id. Compare lists working copies for that same pack id. A selection whose pack id is the adapter's pack id keeps the current editor and Compare lookup. The Task 6 fixture uses a pack id that no adapter owns, so the test cannot pass by importing the adapter's own Pack.
