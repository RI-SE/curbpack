How it works

Warm-start and research help you choose a draft; only check decides pass/fail—not certification.

Not conformity assessment. Not CE marking. Not a notified-body opinion.

Two ways in — same local check

  1. Write then check — optional warm-start: choose checklists, draft house docs (always two options with a Recommended: A or B), optional research brief, then check.
  2. Bring docs then check — put existing policies on the pack paths (or map a partner pack), then check. CyberReady does not ingest portal PDFs; Evidence→Check means files in the repo (or custom pack paths).

CI can run check alone anytime. Either way ends in a review pack for a human to judge and optionally attest.

1. Choose a rule pack

A rule pack is a JSON checklist of structural gates. You pick which packs to run. Frozen catalog today:

  • house-policy — default cold start (house documentation / dependency hygiene)
  • cra-baseline — Cyber Resilience Act (CRA)–shaped annex draft structure (informational)
  • medtech-iec62304 — IEC 62304–shaped overlay (composes with CRA when selected)

Packs are checklists shaped like regulatory annex drafts, not the law itself. Green gates mean the pack rules passed on this tree — not conformity assessment, not CE marking, and not a notified-body opinion. Compose with cyberready init --packs … or .cyberready.json. Warm-start for Write→Check is optional (cyberready pathway) — prefer “choose checklists,” not “pathway to regulation.”

2. Draft choice (Write→Check)

Assistants propose Option A and Option B, state Recommended: A or B with a few reasons, then stop for you. Optional allowlisted research brief informs cites; it never changes check pass/fail. After you pick, run cite-check before owning the prose.

3. Local check

cyberready init then cyberready check evaluates the chosen packs on disk. Dual output: machine-readable findings (JSON) and a short markdown report. Exit 0 = gates passed on this tree; 1 = findings remain. Daily check does not write the buyer one-pager.

4. Review pack — hand to a buyer or auditor

prepare-release (or cyberready share) writes a review pack: gate JSON, action report, executive summary, optional SBOM/VEX drafts, and a buyer one-pager HTML. That is the artifact you hand over. Front = findings. Back = provenance, optional allowlisted Sources (informational), and human sign-off status.

5. Human review and attest

A person judges the evidence. When ready they run cyberready attest, which binds a reproducible state hash into Git Notes (ssh-agent signed when possible). Unsigned ≠ verified. After attest, you can open the local proof/index.html page and compare the bound hash from the evidence pointer—still not conformity assessment.

Check → evidence → human

CyberReady decides pass/fail (deterministic). Humans decide what to claim. Tutors propose only and must re-check; they never greenlight or attest.
