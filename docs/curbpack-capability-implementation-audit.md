# Curbpack capability implementation audit

Audit basis: `curbpack-capability-review.zip` against the capability inventory supplied separately. Status semantics follow that inventory: IMPLEMENTED, PARTIAL, NOT FOUND, UNVERIFIED.

Important test note: `go test ./...` and a broad multi-package test invocation did not complete within the execution limit. Targeted tests completed successfully for pack composition, evaluation, canonical digests, output writes, path containment, SARIF, attestation verification and selected review paths. Therefore this is an implementation audit, not a claim that the complete repository test suite is green.

## Demoable now

The strongest end-to-end implemented capabilities are: versioned/composed packs, local evaluation with explicit check kinds, read-only scan, structured findings and machine output, portable review packs, offline integrity review, deterministic/canonical evaluation plus separate run receipts, content-addressed cache, atomic/contained writes, path/subprocess hardening, privacy washing, no-network/no-hosted core operation, SARIF/CycloneDX/SPDX export, adversarial testing, simple operator flow and agent-facing operation.

## Partially present

The principal partial areas are: general remediation, complete error/outcome semantics across every channel, channel consistency, independent expected-value verification, rich authenticity states, full trust-dimension modeling, resource limits, cancellation, command metadata, schema/CLI evolution, crossing-schema completeness, generic provenance, human-only authority enforcement, release/platform evidence, complete assurance coverage, multi-level acceptance evidence and optional hosted coordination.

## Not implemented

- CAP-30 External evidence ingestion
- CAP-35 Instructional rollback

## Unverified from this ZIP

- CAP-47 Public-history preservation — requires actual Git history.

## Explicit non-capabilities: not gaps

The audit found no reason to turn the SDD's explicit boundaries into implementation defects: Curbpack does not need to make legal conformity/certification/CE conclusions; an LLM need not decide pass/fail; the evaluator need not require a server/database/account; telemetry/payment-controlled evaluation, bespoke PKI, broad Office/PDF/XML parsing, persistent graph DB/query language, or autonomous merge/release/approval/deployment/rollback are not required capabilities.
