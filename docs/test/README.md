# Tests and acceptance evidence

Import and baseline the fresh pilot's tests first; do not reorganize them merely because this directory exists.

For implemented work, preserve the chain **Epic → Story → REQ → Test → Implementation**. Record the relevant story and REQ IDs, test/procedure, actual execution result and gaps. Not every Requirement needs a separate test file; one meaningful test can cover several related assertions.

Include failure/cancellation and preservation cases, not only successful UI paths.
